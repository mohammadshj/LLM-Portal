# نتیجهٔ بررسی نسخهٔ اولیه

این بررسی روی محیط فعلی انجام شده است؛ اتصال تجاری LLM یا سرور عمومی اعتبارسنجی نشده است.

- ساخت imageهای Backend و Frontend با حفظ TLS verification موفق بود.
- migrationهای Django روی PostgreSQL 17 اجرا شدند؛ `makemigrations --check --dry-run` تغییری گزارش نکرد.
- ۱۲ آزمون Backend روی PostgreSQL اجرا و همگی موفق شدند؛ شامل ورود/خروج با CSRF، الزام احراز هویت، جداسازی کاربران، کنترل سهمیه و context، مقایسه با تاریخچهٔ مستقل، خطای جزئی provider، پاک‌سازی و حفظ آمار، مجوز گزارش مدیر و رقابت دو درخواست هم‌زمان برای یک سهمیه.
- `npm run build` شامل TypeScript strict check و Vite build موفق بود.
- `ruff check backend` موفق بود.
- تنظیم Nginx با `nginx -t` بررسی شد. درخواست `/api/health/` از مسیر Nginx به Django و PostgreSQL پاسخ موفق داد.
- آزمون Playwright با Chromium نصب‌شدهٔ محیط انجام شد: ورود کاربر آزمایشی، مقایسهٔ دو مدل نمایشی، ماندگاری تاریخچه پس از reload، گزارش مدیر، تاریخچه در موبایل، حذف گفتگو و خروج موفق بود. در عرض ۳۹۰ پیکسل سرریز افقی و خطای JavaScript ثبت نشد.

برای تکرار آزمون Backend:

```sh
docker compose run --rm backend python manage.py test portal --verbosity 2
```

هر دو مدل این آزمون مرورگر نمایشی بودند. آداپتور واقعی به کلید معتبر، دسترسی شبکه و مدل سازگار نیاز دارد. مصرف نمایشی معیار دقت tokenizer مدل واقعی نیست. بررسی تصویری دسکتاپ و موبایل انجام شد؛ آزمون دسترس‌پذیری جامع و آزمون بار انجام نشده‌اند.

## فونت وزیرمتن و حالت تیره

- ساخت Frontend و بررسی TypeScript موفق بود؛ وابستگی جدیدی اضافه نشد.
- محتوای هر ۱۰ فونت ارسالی در پروژه نگه داشته شد؛ نسخهٔ Variable با نام فایل `Vazirmatn-Variable.woff2` استفاده می‌شود. فایل مجوز OFL از مخزن رسمی فونت همراه فایل‌ها قرار گرفت.
- Playwright روی فایل‌های خروجی production با همان CSP پیکربندی Nginx اجرا شد. مسیرهای API در این بررسی رابط کاربری شبیه‌سازی شدند؛ این بررسی، آزمون تازهٔ Backend یا اتصال LLM واقعی نیست.
- Chromium با اطلاعات فونت رندرشده تأیید کرد که عنوان فارسی از فونت سفارشی Vazirmatn استفاده می‌کند؛ تنها یک درخواست فونت برای نسخهٔ Variable ثبت شد.
- پیروی اولیه و زنده از تم سیستم، تغییر دستی، حفظ انتخاب بعد از reload، همگام‌سازی تب‌ها و کارکرد در صورت مسدودبودن localStorage موفق بود.
- اعمال تم قبل از اجرای React با متوقف‌کردن دریافت bundle برنامه بررسی شد؛ فایل راه‌انداز تم با CSP اجرا شد.
- صفحهٔ ورود، گفتگو و گزارش در دو تم بررسی شدند. در عرض‌های ۱۴۴۰، ۷۶۸، ۳۹۰ و ۳۲۰ پیکسل سرریز افقی ثبت نشد. تصاویر دسکتاپ و موبایل حالت تیره نیز بازبینی شدند.


## اتصال مستقل برای چند سرویس و مدل

- migration `0003` روی PostgreSQL محیط اجرا شد و فرم Admin افزودن اتصال و اتصال مدل به سرویس در آزمون‌ها بررسی شد.
- ۲۳ آزمون Backend روی PostgreSQL موفق شدند، شامل مهاجرت مدل‌های قدیمی، استقلال endpoint و کلید دو سرویس حتی برای model_id یکسان، استفادهٔ چند مدل از یک اتصال، سرویس محلی بدون کلید، نبود fallback به کلید مشترک، توقف اتصال غیرفعال، جلوگیری از دنبال‌کردن redirect با credential و پنهان‌بودن جزئیات اتصال در API.
- مقایسهٔ دو سرویس با خطای یکی از آن‌ها آزموده شد؛ پاسخ موفق و آمار آن ثبت شد و متن خطای خصوصی سرویس در خروجی نبود. آزمون سهمیهٔ هم‌زمان قبلی نیز موفق بود.
- درخواست‌های خارجی جدید با `httpx.MockTransport` شبیه‌سازی شدند؛ کلید واقعی یا درخواست پولی استفاده نشد. موفقیت این آزمون‌ها به معنی تأیید دسترسی به OpenAI، OpenRouter یا دیگر سرویس‌های واقعی نیست.
- `ruff check` و بررسی نبود migration تولیدنشده موفق بودند.

## هم‌زمانی، Streaming و توقف

۴۳ آزمون Backend با Django و PostgreSQL 17 اجرا شدند. آزمون ارتقا از migration شمارهٔ ۰۰۰۳، سؤال بی‌پاسخ و پاسخ موفق قدیمی را در پایگاه داده ایجاد می‌کند. پس از ارتقا، فقط سؤال دارای پاسخ موفق وارد Context مدل می‌شود و توکن‌های همان پاسخ حفظ می‌شوند.

- آزمون‌های HTTP تفاوت خطاهای ۴۰۰، ۴۰۱، ۴۲۹، ۵۰۰، timeout، قطع اتصال و پاسخ نامعتبر را بررسی کردند. پاسخ دارای reasoning، مصرف ناقص، متن فارسی تقسیم‌شده بین قطعه‌ها، پایان ناقص SSE و fallback به JSON نیز با سرویس آزمایشی پوشش داده شدند.
- آزمون‌های PostgreSQL و ASGI رقابت برای اعتبار مشترک، ارسال تکراری، جلوگیری از دو ارسال فعال در یک گفتگو، تسویهٔ مستقل مدل‌ها، قطع کلاینت و بازیابی رزرو منقضی را بررسی کردند.
- در آزمون Playwright، Chromium با یک نشست کاربر از مسیر Nginx در سه گفتگو درخواست فرستاد. سرویس HTTP آزمایشی پایان پاسخ‌ها را تا دریافت فرمان آزمون نگه داشت. مرورگر بخش اول را پیش از پایان دریافت کرد. توقف گفتگوی دوم اتصال بالادست همان گفتگو را بست. دو گفتگوی دیگر تکمیل شدند. در مقایسهٔ سه مدل نیز پاسخ‌های دو مدل با وجود خطای ۵۰۰ مدل سوم باقی ماندند. متن، وضعیت و سهمیه پس از بازخوانی صفحه و از طریق پایگاه داده بررسی شدند.

ساخت TypeScript و Vite، بررسی Ruff، تطبیق migrationهای Django و اعتبارسنجی تنظیم Nginx نیز انجام شد. آزمون اتصال DeepSeek از IP شرکت و آزمون ظرفیت زیر بار تولید اجرا نشده‌اند. [روش اجرای آزمون مرورگر](../tests/browser/README.md)

## Thinking و مصرف توکن

روی PostgreSQL 17 در ساخت عادی از ۵۵ آزمون، ۵۴ مورد موفق بود و آزمون کتابخانهٔ اختیاری tokenizer کنار گذاشته شد. در ساخت دارای `INSTALL_LOCAL_TOKENIZERS=1` هر ۵۵ آزمون اجرا و موفق شد. این آزمون با tokenizer محلی نمونه، بارگذاری آفلاین و غیرفعال‌بودن truncation را بررسی می‌کند. تطابق tokenizer تجاری هیچ‌یک از سه مدل هدف در محیط آزمایش تأیید نشده است.

- آزمون‌های Backend سطوح اجباری و اختیاری، رد سطح یا شناسهٔ نامعتبر پیش از رزرو، JSON قدیمی، تفکیک chunkهای استدلال و پاسخ، نبود متن نهایی، نگهداری مصرف گزارش‌شده پس از خطا، جمع بدون تفکیک، پرهیز از دوباره‌شماری، بازپخش محدود به همان مقصد و قطع اتصال حین استدلال را پوشش دادند. آزمون مهاجرت، حفظ متن و مصرف قدیمی و نامعلوم ماندن استدلال گذشته را بررسی کرد.
- در Playwright سه گفتگو از یک نشست روی Nginx و Chromium اجرا شد. سرویس Mock HTTP پیش از اجازهٔ آزمون هیچ متن نهایی نمی‌فرستاد. مرورگر در همان فاصله دو قطعهٔ استدلال را در کارت مدل نمایش داد. سطح مجزا به سرویس رسید، حالت Off بخش استدلال نداشت، توقف یک گفتگو اتصال همان مدل را بست و خطای ۵۰۰ یک مدل پاسخ دو مدل دیگر را از بین نبرد. بازیابی متن از PostgreSQL بعد از Refresh، جدایی متن نهایی و استدلال، حالت روشن و تاریک و نبود سرریز افقی در عرض ۳۹۰ پیکسل بررسی شد.
- `tsc --noEmit`، ساخت production با Vite، Ruff، `makemigrations --dry-run --check`، اجرای migration شمارهٔ ۰۰۰۶، `nginx -t` و درخواست سلامت از مسیر Nginx موفق بودند. آزمون‌ها از کلید پولی یا API شرکت استفاده نکردند.

فایل‌های جدید شامل `backend/portal/thinking.py` برای اعتبارسنجی و ساخت پارامترهای درخواست، `backend/portal/tokens.py` برای شمارش و خواندن Usage، `backend/portal/migrations/0006_thinking_and_token_usage.py`، `backend/portal/test_thinking.py` و `docs/thinking.md` هستند.

فایل‌های تغییرکرده در Backend شامل `models.py`، `admin.py`، `serializers.py`، `providers.py`، `services.py`، `streaming.py`، `views.py`، آزمون‌های اتصال، ارائه‌دهنده و HTTP و `backend/Dockerfile` هستند. در Frontend فایل‌های `main.tsx`، `useChats.ts`، `stream.ts`، `types.ts`، `MessageList.tsx` و `style.css` تغییر کردند. سناریوی مرورگر و سرویس کنترل‌شدهٔ آن در `tests/browser` و راهنماهای README، Streaming و اعتبارسنجی نیز به‌روز شدند.
